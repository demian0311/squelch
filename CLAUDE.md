# Squelch

RTL-SDR receiver for Omarchy (Hyprland). Tauri 2 shell + Rust engine + Svelte 5 UI.

## Layout
- `crates/radio/` — engine, no UI deps. `device.rs` (librtlsdr FFI + `SimSource`), `dsp.rs`, `demod.rs` (WFM/NFM/AM/USB/LSB → 48 kHz), `spectrum.rs` (FFT rows), `detect.rs` (signals above floor), `bands.rs` + `default_bands.toml`, `theme.rs` (Omarchy colors), `audio.rs` (cpal), `engine.rs` (receive thread, `Command`/`Row`/`Status`).
- `src-tauri/` — commands `setup bands save_bookmark delete_bookmark notify theme start tune set_mode set_gain set_volume set_playing iss`; polls theme + bands file every 2 s and emits `theme` / `bands` events.
- `crates/radio/src/sonde/` — weather-balloon decoders. `Scanner` gives each narrow detected signal a `Channel` (mix + 2-stage decimate to 48 kHz FM) and runs every `FrameDecoder` on it; `fsk.rs` symbol recovery; `dfm.rs` (DFM-06/09/17), `rs41.rs` (+ `rs.rs` Reed-Solomon, `geo.rs` ECEF). Channels that decode nothing for `TRY_FOR` are set aside for `RETRY_AFTER`. Engine runs it only after `Command::SetSondes(true)` (UI sends it in bands with `decoder = "radiosonde"`).
- `crates/radio/src/acars/` — aircraft messages (ARINC 618). Fixed `US_CHANNELS_HZ` inside the capture (bursts are too short for the detector to open a channel in time), all decoded all the time after `Command::SetAcars(true)` (UI sends it in bands with `decoder = "acars"`). `msk.rs`: mix + `Decimate` to 48 kHz, envelope, 24 kHz audio, mix by 1800 Hz, discriminator; 2400 Hz = bit same as last, 1200 Hz = differs; `PHASES` bit clocks with their own framers, duplicates dropped. `frame.rs`: SYN SYN SOH (inverted SYN flips the stream), odd parity, CRC-16/KERMIT after SOH through ETX/ETB, one bad-parity byte repaired against the CRC; downlinks (digit block id) carry MSN + flight. Status carries only `SEND_FOR` of messages; the panel (`lib/acars.ts` `mergeMessages`) keeps its own list, seeded from the log. `joinBlocks` joins multi-block messages and drops retransmissions (rule inferred, no published source), `acarsPosition` reads the documented layouts of labels 16/20/21/22/H1, `labelName` only says what a published source says. The band always enters at `ACARS_CENTRE_HZ` (5 of 6 channels fit; a remembered frequency could push out 131.55). Verified live 2026-11-02: label 22 position report from N335FR parsed to 26.095, -79.781. 2026-11-03 06:33-07:18 local (08:33-09:18 Miami): 52 blocks, all on 130.025 and 131.55 MHz; labels 21 and 22 from N705FR 6 s apart both gave 26.082, -80.075. Each block of an H1 message repeats its header (`#DFB`) and the last letter of the MSN numbers the blocks, so `joinBlocks` drops the repeat and shows `…` for blocks not heard. Positions also sit inside H1 `#DFB` text (`D3M`, `/WX`; layout `N25498W079598` + time) and are not read: no published layout found yet; `#M1BREQPWI` holds route points, not positions.
- `ui/src/components/AirplanesScreen.svelte` + `lib/airplanes.ts` — the novice screen on band `air` (overlay in `main`; the rail hides the `adsb`/`acars` bands via `oneAirplanes`, shown as "Airplanes"). Everything hangs off one plane: map (`AircraftMap.svelte`: repeater-map terrain via `lib/ground.ts`, `airPalette` slight tint, airports, `placeLabels`: symbols, the ring distances and the attribution are reserved first, then names go on a side or a corner, picked plane first; airports draw above the trails), messages matched by tail or flight (`messageSender`, `isFrom`; ICAO to IATA in `lib/airlines.json`, `ui/scripts/airlines.py`), `talkGuess` (labelled guess from nearest big airport, height, climb, route; none above 18,000 ft; nothing broadcasts who a plane talks to). Trails: `trailPieces` colours by `HEIGHT_BANDS` and fades over `TRAIL_FADE_MS` (picked plane `TRAIL_KEEP_MS`), recomputed per `FADE_TICK_MS`. `crates/radio/src/planeinfo.rs`: type, owner, thumbnail from api.adsbdb.com by address when a plane opens (no key, curl, `~/.cache/squelch/aircraft/`, offline caches nothing; photo comes as a data URL because of the CSP); `open_link` hands `https://` pages to xdg-open (`lookupLinks`). Seen live 2026-11-03: N37547 Boeing 737-9, United, with photo. Tabs Overhead now / Messages / Earlier are icons (plane, msg, clock; the word is the tooltip); a plane row carries a chevron (down when open, click again closes); the channel card is one row (play, name + MHz, a help marker whose tooltip holds the why), and the look-up links carry the box-arrow icon. Frequencies come only from OurAirports' airport list (tower, ground, approach, departure, traffic channels per airport; 6,541 of 8,246 airports have one, 2026-11-04); nothing en-route, so above `TOO_HIGH_FT` there is no guess. "See the radio" and "Back to the map" switch to the waterfall. While watching, `Command::AirTurns` alternates the dongle `AIR_TURNS` between `ADSB_CENTER_HZ` and `acars::CENTER_HZ` (`Turns` in `engine.rs`: `SETTLE_SECS` rest after a retune, a `Tune` keeps the centre, mode none); The top bar stays (title `Airplanes` or the channel; play is disabled while watching, pausing a channel is `stopListening`, which also quiets the radio). The card's play/record are the top bar's. While watching, the one `Waterfall` sits under the list in the side panel (`.sidewf`, never under about two rows; the list scrolls), its view follows the capture (`status.center_hz`, so it clears at each turn: row centres are 16-bit bin offsets), the big digits show that centre and the sub-line says which turn it is; rows sort by the minute of their last position, then distance (`aircraftRows(.., true)`). Listen turns the turns off, freezes the list, and the one `Waterfall` (App's `wfView` snippet) renders above the paused map instead of in the Spectrum pane, so it remounts blank on each switch; after stopping, planes from before are `carried` for `CARRY_MS` and fill a re-heard plane's missing name. `messageReading` says what a message says (published layouts for labels 21/22/SA; `#CFB` faults, `#M1B` runway and route, schedules and departure messages are patterns read off air 2026-11-03) and owns up to the rest (`NO_KEY`); joined text may open with `…`. `Adsb::skip` must also advance the demod's sample count, or planes age out (found live 2026-11-03). Measured 2026-11-03, Miami, real dongle, `air_turns`: 10 aircraft and 6.8 with position vs 11 and 7 on planes alone, retune ~30 ms; 11 ACARS blocks in about 20 min in the app. Message-to-plane match and the screen's message pins not yet seen against live data as of 2026-11-03. Airports: `crates/radio/src/airports.rs` + `airports.txt` (OurAirports, public domain; `ui/scripts/airports.py`), commands `airports_near airports_by_code`. Unpublished layouts read on air 2026-11-03: `routeIn`, `positionsIn` (`N25498W079598` + 6-digit time in H1 `#DFB`).
- `crates/radio/src/airlog.rs` — aircraft kept across runs: JSON lines per UTC day in `~/.local/state/squelch/aircraft/`. The engine sends `Line`s to an `airlog` thread: `a` attributes when they change, `p` a position every `LOG_EVERY`, `m` each ACARS block. Nothing from the simulator is logged. Pruned at `KEEP_DAYS` / `MAX_BYTES`, oldest day first, never today. `flights` folds lines into flights (`FLIGHT_GAP_MS`); commands `air_flights air_track air_tracks air_messages`. UI: Flights log tab on both aircraft bands (day groups, find, click draws the track), map trails (`extendTrails`, `TRAIL_KEEP_MS`, seeded from the log), click a plane or row for `aircraftFacts`. The aircraft bands are exempt from dead-air hiding (`DEAD_AIR.keep`).
- `crates/radio/src/rds/` — FM station data. `phy.rs`: pilot PLL ×3 → 57 kHz mixdown, Costas for residual phase, PSK-rate timing (reuses `sonde::fsk::Fsk`), biphase pairing by energy, differential decode. `blocks.rs`: sync needs two blocks in order, 2-bit burst correction, loss at >42 bad of 50. `mod.rs`: PS (0A/0B), RadioText (2A/2B), RT+ title/artist. Runs inside the WFM `Demodulator` on the 240 kHz MPX.
- `crates/radio/src/hd/` — HD Radio. `ffi.rs` dlopens libnrsc5 (loader path, then `~/.local/lib/libnrsc5.so`) and mirrors the header's event layouts — recheck them against `include/nrsc5.h` if nrsc5 is upgraded. `mod.rs`: `Hd` mixes the tuned station out, decimates to 800 kHz, cubic-resamples to 744187.5 S/s and pipes it to nrsc5 on its own thread; digital audio replaces analog after `PRIME_SECS` queued. The decoder runs only while digital audio is asked for: `Command::SetHd(Some(program))` starts it, `SetHd(None)` stops it (it costs a fifth of a core). `sidebands` alone lights the card's HD chip, which is how it is asked for. The Stations panel's top strip shows it while it runs, traffic and radar get their own tab; it remembers the program per station in `state.json` (`hd`). `mark_sidebands` also tests every signal in the capture (`Detected.hd`, `None` when one side is off the capture), remembered in `Heard.hd`. Live false-positive rate unmeasured as of 2026-11-02: a station with neighbours on both sides 200 kHz off could read as HD.
- `crates/radio/src/iss/` — space station passes, offline. `mod.rs`: SGP4 (`sgp4` crate) on the TLE cached at `~/.cache/squelch/iss.tle`, TEME→ECEF by IAU sidereal time, pass search (30 s steps, 1 s bisection). `fetch` uses `curl` against CelesTrak; the shell refreshes when the cache is >12 h old, trying at most every 2 h (CelesTrak blocks faster polling). `place.rs`: US ZIP centroids (`zips.txt`, Census 2020 ZCTA, 0.1°) and state centres (`states.txt`, area-weighted county points). UI (`lib/iss.ts`) widens passes by `slack` as the TLE ages, warns past 3 days, puts a dot on the rail's `iss` band while it may be overhead, and draws `IssMap.svelte` (d3-geo + world-atlas land-110m, offline) in the Space station panel from the `iss_track` command — whole world unless a pass is under way and the channel reads ≥ `RECEPTION_DB`; location lives in `settings.toml`, set in the Settings drawer, and also picks nearby repeaters.
- `crates/radio/src/p25/` — P25 Phase 1 public-safety trunking, `Mode::P25` (bands in group `safety`). `P25` (mod.rs) runs instead of the demodulator: searches carriers within `SEARCH_PPM` of the tuned control channel, follows unencrypted Phase 1 grants (retunes the dongle when the voice channel is outside the capture, restores it after), ends calls `HANG_SECS` after the last good LDU. Crystal error = control channel's own announced frequency vs where it was heard; applied to voice channels. Voice from another NAC (co-channel distant site) or with most frames damaged is muted. `phy.rs` C4FM at 48 kHz, timing per sync; `tsbk.rs` control messages; `voice.rs` LDU layout + DSD's IMBE interleave; `mbe.rs` dlopens mbelib (`pacman -S mbelib`), mirrors `struct mbe_parameters`. Verified live 2026-10-31 on Colorado DTRS site 3-55 (773.79375 MHz, NAC D17): 23 calls followed in 180 s, most 0–15% damaged frames. No BCH on the NID, no Phase 2.
- `crates/radio/src/look.rs` + `lib/ems.ts` + `EmsStrip.svelte` — all of EMS in one picture. The rail shows one EMS entry over the stored bands `ps700` and `ps800` (`oneEms`; Bookmarks keeps them apart). `Command::BandLook(ranges)` borrows the dongle every `EVERY_SECS` and hops across the ranges (`HOP_HZ`, `SETTLE_SECS` + `ROWS_PER_HOP` a hop); nothing is heard or drawn during a look, status `center_hz` stays home, a P25 call or an open squelch holds it off, and tuning aborts it (`RETRY_SECS`). Each hop has its own floor; a cell (`CELL_HZ`) holds the strongest bin, leaving out `DC_BINS`. A line rides in the status for `SEND_FOR_SECS`; `addLine` keeps `STRIP_ROWS`. A click snaps to a signal in any kept line (`stripPick`) and tunes it.
- `crates/radio/src/nxdn/` — NXDN (Icom IDAS, Kenwood NEXEDGE) at 2400 symbols/s from FM audio: frames, link field, SACCH/FACCH/CAC past their CRCs, message names and site fields. Probe only, not in the engine; no voice. Layouts from OP25 and DSD-FME (both GPL). Verified 2026-11-03 on audio recorded from the app at 462.7455 MHz: a trunking control channel, regional system 96 site 42, radio access number 42 (issue "Warble on 462.7455 MHz"); not yet run on the dongle directly.
- `crates/radio/src/adsb/` — aircraft (Mode S extended squitter, DF17/18) on 1090 MHz. `phy.rs`: magnitude of the whole capture, preamble gate then `PHASES` sub-sample starts, chips as area under the magnitude (1.2 samples each at 2.4 Msps), CRC-24 with one-bit correction. `msg.rs`: callsign, altitude (25 ft and Gillham), velocity, CPR fields; `cpr.rs`: even/odd pair (`PAIR_SECS`) then local against the last position (`LOCAL_SECS`), jumps past `MAX_KM_PER_SEC` dropped. `Adsb` keeps aircraft by address for `KEEP_SECS`, sample clock as time; a corrected frame never creates one. Engine runs it after `Command::SetAdsb(true)` (UI sends it on bands with `decoder = "adsb"`); status `adsb`. UI: `lib/adsb.ts` + `AircraftMap.svelte` in the Aircraft panel, distance from the Settings location. Also reads category, surface positions (`surface_local`, reference = own last fix or `Command::SetSite`), GNSS height, status (TC 28: squawk, emergency, collision advisory), target state (TC 29: selected altitude/heading, altimeter, modes), version (TC 31) and replies DF0/4/5/11/20/21. Replies overlay the address on the parity, so they count only for an address in `Demod::known` (heard with a real check); DF11 only with syndrome 0, and an address known from DF11 alone needs `MIN_REPLIES`. Comm-B contents (DF20/21 MB) not read. `ident.rs`: country (`countries.txt`) and registration from the address, both from tar1090. Synthetic I/Q (pulses area-sampled) decodes all frames at 17 dB per sample, 85% at 13.5 dB. Verified live 2026-11-02, Miami, indoor antenna: 6–10 aircraft, map, trails, details; EJA127 derived N127QS (a NetJets-pattern tail). Soak 2026-11-02 23:17 to 2026-11-03 01:17, release build on the real dongle: engine process 225-231 MB flat, WebKit 520-720 MB with no trend, ~12% CPU (`ps`, lifetime average), log 81 kB, 78 addresses, none over 6 degrees from Miami, 3 with neither callsign nor position, all in the US address block. Cost: the gate's pulse sums are one vectorised pass per block, the quiet gaps come off the running sum, and a candidate's chip edges are read once each; `~/.local/state/squelch/bench/adsb-2026-11-04-1090MHz-20s.u8` (Miami, real dongle, 20 s) through `adsb_file` must give 3 aircraft and 93 frames, and took 575 ms (2.9% of real time) on 2026-11-04 against 1640 before; `bench` 26 ms per second of simulated capture (was 61–81).
- `crates/radio/src/repeaters.rs` — parses RepeaterBook's Google Earth KML exports (last seen 2023-02-17, in a public Drive folder "Google Earth Ham Repeaters (United States)"; "0. United States All-In-One" holds one .kmz with every state, about 19k on air, per-state folders hold single lists). Modes come from list names ("Colorado DMR.kml"), which in the US-wide file are inside it (`parse_export`). Output `~/.config/squelch/repeaters.toml`, the whole US on eagle since 2026-11-02, never committed (RepeaterBook data). `Repeaters::shared` parses it once per file change, 164 ms on eagle, on a blocking thread. Shell serves it as `repeaters` (nothing without a location; a state location keeps that state, by RepeaterBook's state_id = FIPS in `states.txt`) and emits `repeaters` on change; `channels.ts` `setRepeaters` makes it the channel plan of each ham band without a fixed plan. `lib/repeaters.ts` + `RepeaterMap.svelte`: the Repeaters panel on bands in `REACH_KM` (one guessed reach per band; the export has no power or height); repeaters also in a DMR/P25/NXDN/D-STAR/M17 file draw dashed as maybe digital-only. The panel is the map alone: the slider's `RANGES_KM` (`repeaters.range` in `state.json`), on-air circles carrying the call, wider for a stronger signal (`ringReach`), the title's pin opening Settings at the location. It reads `repeaters_map` (`within` `MAP_KM`, every repeater on a shared frequency; fetched the first time a band with a map opens, kept until the location or file changes), not the channel plan's nearest-per-frequency `repeaters`, so far repeaters have no channel name. Only imported states draw; a band with none near says so in the panel. The map's ground: `crates/radio/src/terrain.rs` fetches AWS Terrain Tiles (terrarium PNG, zoom 8, no key) with curl into `~/.cache/squelch/terrain/` (`terrain_tile` command); `lib/terrain.ts` shades them in theme colours (`GROUNDS`: one image per stop, zoom 8/7/6) and the result is saved in `~/.cache/squelch/ground/` under `groundKey` (`ground` / `save_ground`). State lines and highways are bundled in `lib/maplines.json`, written by `python3 -I ui/scripts/maplines.py` (us-atlas states + Natural Earth roads).

Dropping the recorder (stop or engine exit) joins the thread and ends the stream, granule trimmed to the real length. Files: `<XDG music>/squelch/` (else `~/Music/squelch`), `2026-11-01T153012Z 101.100MHz wfm.opus` (UTC). ## Wire format
Spectrum rows and status: the page pulls them with the `feed` command (`src-tauri/src/feed.rs`, decoded by `lib/feed.ts`), one request at a time; the backend keeps the newest `MAX_ROWS` rows and the latest status, and a pull waits up to `BATCH_WAIT` for `BATCH_ROWS` rows (a status returns at once): 2026-10-31 this cut script evaluations from 34/s to 14/s and the page main thread from ~20% to ~16%. The body goes back as base64 in a `String`: on Linux Tauri 2.12 a raw `Response` body reaches the page JSON-encoded as a number array in release builds (dev gave an `ArrayBuffer`), found 2026-10-31 as a blank waterfall. Never push rows over a Tauri `Channel`: a row above 1 KiB costs an eval plus a fetch, and a page that falls behind queues them inside WebKit until its watchdog kills it (2026-10-31: ~2 MB/s growth, SIGABRT). A row is 8-byte f64 LE capture centre, then `FFT_SIZE` u8 bins. Byte 0 = `floor - BELOW_FLOOR_DB`, 255 = `RANGE_DB` above that (constants in `engine.rs`, sent to UI via `setup`).

## Commands
- Engine tests: `cargo test -p radio --release`
- Release binary that serves the built page: `pnpm build && touch src-tauri/build.rs && cargo build --release -p squelch --features tauri/custom-protocol` (or `pnpm tauri build`). A plain `cargo build --release` loads the dev URL and shows a blank window.
- Radio-thread profile: run with `SQUELCH_PROFILE=1`; every `PROF_EVERY` it prints the share of each stage to stderr (`Prof` in `engine.rs`). "read" is time waiting on the dongle.
- Real-dongle probe: `cargo run -p radio --release --example probe -- 101.1 wfm 4`
- Stage timings: `cargo run -p radio --release --example bench`
- UI tests / types: `pnpm test`, `pnpm check`
- Decode a recording: `cargo run -p radio --release --example sonde_file -- <wav>` (mono = FM audio, stereo = I/Q). Verified 2026-10-30 on rs1729's `rs41/wav/20140717_402MHz.wav` (RS41 K1930308, 114 frames) and `iq/dfmIQ.wav` (DFM-06 314377).
- HD Radio cost: `cargo run -p radio --release --example hd_bench` times the front end (`hd::FrontEnd`) and libnrsc5 on a second of noise. 2026-10-31 on eagle: front end 21 ms, nrsc5 122 ms (live with a signal the `hd` thread takes ~21% of a core, nearly all inside libnrsc5; a rebuild with `-DCMAKE_BUILD_TYPE=Release -DUSE_SSE=ON -march=native` measured the same live, 22.8% vs 21.8%, so the cost is the decoder's own). `hd_probe` right after another dongle user exits falls back to the simulator: wait a few seconds between runs.
- HD Radio live: `cargo run -p radio --release --example hd_probe -- 106.7 0 60 <dir>` prints decoder state and writes pictures (base64) to `<dir>`.
- ACARS live: `cargo run -p radio --release --example acars_probe -- <secs> [centre MHz]` prints every block (default centre 130.5 MHz covers 5 of the 6 US channels).
- RDS offline: `mpx_dump -- <MHz> <secs> <out.f32>` records MPX, `rds_file -- <out.f32>` prints pilot lock, block stats and decoded info.
- Taking turns live: `cargo run -p radio --release --example air_turns -- <secs planes only> [planes s] [messages s] [secs in turns]` prints the plane counts every 30 s.
- NXDN: `cargo run -p radio --release --example nxdn_probe -- <file.wav>` (mono 48 kHz FM audio) or `-- <MHz> <secs>` (close the app first) prints frames and every message past its check. App audio can be recorded while listening: `pactl list short sink-inputs`, then `parec --monitor-stream=<id> --format=s16le --rate=48000 --channels=1 --file-format=wav out.wav`.
- ADS-B live: `cargo run -p radio --release --example adsb_probe -- <secs>` tunes 1090 MHz and prints the aircraft table every 5 s.
- Raw capture to a file: `cargo run -p radio --release --example iq_dump -- <centre MHz> <secs> <out.u8>` (8-bit I/Q as the engine reads it, first second after the tune skipped). `adsb_file -- <file.u8> [passes]` runs the aircraft decoder over one in engine-sized blocks and prints the time, aircraft and frames: the regression gate for `adsb/phy.rs`.
- Space station passes: `cargo run -p radio --release --example iss -- <tle file> <zip | state | lat lon> [hours]`. Ground point matched api.wheretheiss.at to 0.01° on 2026-10-31.
- P25: `p25_scan -- <secs per step>` lists always-on carriers in 769–775 / 851–869 MHz (raw, crystal-uncorrected); `p25_probe -- <secs> <MHz>…` reports frame syncs, NAC, frame types and decoded TSBKs; `p25_live -- <control MHz> <secs> [out.f32]` follows calls and writes 48 kHz voice.
- Crystal error: `cargo run -p radio --release --example crystal -- 101.1` measures on a strong FM station, applies it, measures again.
- Live sweep of 400–406 MHz: `cargo run -p radio --release --example sonde_scan -- <secs per step>`.
- HD Radio sidebands across 88–108 MHz: `cargo run -p radio --release --example hd_scan -- <secs per step> [MHz… to profile]`.
- Repeaters file: unzip the US-wide .kmz, then `cargo run -p radio --release --example repeaters -- doc.kml` (or `"Colorado All.kml" "Colorado DMR.kml" …`) overwrites it with every on-air repeater passed; the shell keeps those within `NEARBY_KM` of the location (a state keeps its own), nearest per output frequency.
- App: `./run.sh` (release build, rebuilt when a source file is newer than it; installs deps if missing, refuses while gqrx/SDR++ runs). `./run.sh sim` sets `SQUELCH_SIM=1` for the simulated receiver. `./run.sh dev [sim]` is `pnpm tauri dev`: hot reload at several times the CPU, so judge no cost by it.

## Facts
- Page cost rules, from a core pegged on the aircraft map (2026-11-03). Data replaced whole is `$state.raw`: `$state` wraps it in a proxy that every read goes through. A component prop reads the parent's value through a getter, so a `$derived` using `centre` or `halfKm` from an object made anew per status runs per status; put the number in its own `$derived`, which only passes on a change. Nothing per status searches a list per row. Waterfall draws once per batch in `requestAnimationFrame`. Real dongle on eagle, release, % of one core for engine + WebKit, before and after: FM 101.5 77 -> 41-61 (HD off); Aircraft tracking 126 -> 67-78, WebKit memory 680 -> 291 MB. The high ends came just after a 5-minute build, with the chip at 82 C; these samples swing that much with heat and other load, so compare builds in alternating runs. Page script fell from 4800-7000 to 100-220 profiler samples per run. `BATCH_WAIT` 200 ms measured no saving, so it stayed at 100. Hiding the whole page leaves WebKit at 11% against 30% visible: what remains is spread across rendering, so a different UI framework has at most about 20 points to gain.
- A live "% of a core" on eagle is measured at 700 MHz: the `powersave` governor with `balance_power` preference keeps the cores there while the radio thread waits on the dongle half the time, and a saturated offline run turbos to 3.2 GHz (sampled `/proc/cpuinfo` 2026-11-04). So `SQUELCH_PROFILE` percentages and `ps` run about 4.5× the offline cost in cycles (ADS-B live read 39% of wall while `adsb_file` on the same signal took 8%). Judge a change by the offline benches (`bench`, `adsb_file`, `hd_bench`), and compare live runs only against each other.
- Audio: `audio.rs` uses a lock-free ring (`rtrb`), so the callback never waits on the radio thread, and asks for `DEVICE_FRAMES` per callback. Errors print one dated line per `REPORT_EVERY` with a count. The burst of underruns reported 2026-11-03 was not reproduced: a trivial cpal callback under 6 busy threads got 0, and none in test runs before or after these changes, so the cause is unproven (issue "Audio underruns, fans and an unresponsive window while running").
- WebKitGTK on eagle (2-core i5-7360U, 2× scale) repaints and lays out on its main thread. No endless animation at all: even an `opacity` keyframe on the compositor keeps the whole window compositing at 60/s (measured 2026-10-31, release build); a state is shown by a steady style. One exception, the owner's call 2026-11-01: the Repeaters map's on-air circles (`.blip i`), which run only while a repeater in view is on air or within `HOLD_MS` of it; their cost on eagle is unmeasured. One-shot transitions only on `transform`/`opacity` of HTML elements (never SVG children, `box-shadow`, `width`); no `animate:flip` on a list rebuilt per status (it forces one page layout per row). Measured 2026-10-31 through `WEBKIT_INSPECTOR_HTTP_SERVER=127.0.0.1:9333` (Timeline and ScriptProfiler over its WebSocket).
- FFT bin i of a row is centred on `lo + i * binHz`, no half bin (`binAt`, `detect.rs`, the shader): all three drew and reported signals 586 Hz high until 2026-11-03. Checked by a test through `Spectrum` + `detect` and by reading pixels from both renderers in headless Chromium; not yet on a real CB carrier.
- Waterfall: `lib/waterfall/gl.ts` keeps `ROWS` rows in a WebGL texture ring in capture coordinates and maps the view in the shader, so a row is one small upload and a zoom is two uniforms; `cpu.ts` is the 2D fallback; `waterfall = "cpu"` in `settings.toml` forces it (checked live 2026-10-31: draws, zoom lines up, page main thread ~6 points higher than WebGL). The spectrum line is a 2D canvas, one `Path2D` at one point per CSS pixel. The spectrum transform runs every `EVERY` frame (`spectrum.rs`).
- DSP hot paths (`dsp.rs`): FIR dot products and the mixer have AVX2+FMA kernels chosen at runtime (`has_avx`), with plain twins the tests compare against; `Decimate::new(rate, pass, stop, factor)` splits an even factor ≥ 4 into two stages; `fast_atan2` (≤ 2e-5 rad) for FM discrimination and the pilot PLL, which runs per `BLOCK` (`rds/phy.rs`). `process_mixed` on `Decimator`/`Decimate`/`Demodulator` has the mixer write straight into the filter's buffer (one copy and one pass over the block less; a narrow channel's cost at the capture rate was mostly those passes). Magnitudes are `norm_sqr().sqrt()`, never `norm()` (hypot, ten times the cost). Bench 2026-10-31 on eagle: WFM 105 → 26 ms per second of capture, NFM 58 → 16, AM 56 → 9, USB 101 → 14, sondes 183 → 77. Bench 2026-11-04: WFM 29, NFM 18, AM 10, sondes 48 (4 channels), ACARS 60 (5 channels), ADS-B 26; `SimSource` 810 → 200 (oscillators turned by complex multiplies, series for the modulation's small angle).
- eagle is a MacBookPro14,1; logind's lid action is hibernate (`/etc/systemd/logind.conf.d/30-lid.conf`), `/sys/power/disk` mode shutdown, `mem_sleep` deep. Whether the RTC alarm wakes it from either, and whether the engine's dongle reopen (a read error closes and reopens `RtlSdr`) works after resume, is unverified as of 2026-11-01: testing means putting the machine to sleep.
- Dongle on eagle: generic RTL2832U + R820T, 24–1766 MHz, no HF. DVB driver blacklisted in `/etc/modprobe.d/blacklist-rtlsdr.conf`.
- Moving or zooming the view never restarts audio: `Command::Tune` clears audio and squelch only when `tuned_hz` changed (test `repeating_a_tune_leaves_the_channel_alone`: 2026-11-01, 46.6 dB still vs 19.2 dB dragging before the fix). `captureCenter` keeps the tuned frequency in the capture as long as view and tuned fit within `rate * 0.45` of one centre; past that the view wins and the engine mutes rather than play the alias. A centre move still flushes queued samples; HD keeps decoding (`Hd::set_offset`, each queued block carries its offset), riding out the gap on its audio queue. Unit-tested 2026-11-01; not yet heard live.
- Capture is 2.4 Msps (`SAMPLE_RATE`); UI view span capped at 0.8× that. The live waterfall stays that narrow; only the EMS strip (`look.rs`) sweeps.
- User bands file: `~/.config/squelch/bands.toml`, written from defaults on first start. `bands::add_new_defaults` then adds default groups/bands not listed in `~/.local/state/squelch/default_bands_seen` (ids offered before); with no record yet, only whole missing groups. Edits and deletions are kept.
- Theme source: `~/.local/state/omarchy/current/theme/colors.toml`.
- Sonde types near eagle (NWS list 09-25): every nearby site flies GRAW DFM-17; Denver (KDNR) lists none. RS41 is the other US type. Simulator includes a DFM-17 at 403.3 MHz.
- `cargo build` while `pnpm tauri dev` is rebuilding corrupts the shell crate's link (undefined hidden symbol): stop dev, `cargo clean -p squelch`, rebuild. If that still fails (2026-11-01: it did, after a clean of the shell crate alone), `cargo clean --profile dev`; the rebuild took 9 min on eagle.
- The dongle streams via `rtlsdr_read_async` on its own thread into a `QUEUE`-buffer channel. Blocking `read_sync` dropped 15–25% of samples (found 2026-10-30: rows/s ~24 not 30, pilot phase random, RDS dead).
- eagle's dongle crystal runs ~57 ppm fast: FM carrier offset on 101.1 MHz, 2026-10-31 (`crystal` example); after correcting 57, residual ~1 ppm. The engine measures it on any strong FM station tuned on the 100 kHz grid (`MEASURE_SECS`, `MEASURE_SNR_DB`) or a P25 control channel; the UI applies it via `set_ppm` (librtlsdr `rtlsdr_set_freq_correction`, positive = crystal fast) unless set by hand in Settings: by hand is `crystal_ppm` in `settings.toml`, measured is `ppm.measured` in `state.json`.
- libnrsc5 is not packaged: build theori-io/nrsc5 with cmake (CLI needs system `libao`), copy `build/src/libnrsc5.so` to `~/.local/lib`. Without it the HD panel shows the install hint. GPL-3; its audio codec is patented.
- Only one program can hold the dongle; close gqrx/SDR++ first.
