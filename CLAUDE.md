# Squelch

RTL-SDR receiver for Omarchy (Hyprland). Tauri 2 shell + Rust engine + Svelte 5 UI.

## Layout
- `crates/radio/` — engine, no UI deps. `device.rs` (librtlsdr FFI + `SimSource`), `dsp.rs`, `demod.rs` (WFM/NFM/AM/USB/LSB → 48 kHz), `spectrum.rs` (FFT rows), `detect.rs` (signals above floor), `bands.rs` + `default_bands.toml`, `theme.rs` (Omarchy colors), `audio.rs` (cpal), `engine.rs` (receive thread, `Command`/`Row`/`Status`).
- `src-tauri/` — commands `setup bands save_bookmark delete_bookmark notify theme start tune set_mode set_gain set_volume set_playing iss`; polls theme + bands file every 2 s and emits `theme` / `bands` events.
- `crates/radio/src/sonde/` — weather-balloon decoders. `Scanner` gives each narrow detected signal a `Channel` (mix + 2-stage decimate to 48 kHz FM) and runs every `FrameDecoder` on it; `fsk.rs` symbol recovery; `dfm.rs` (DFM-06/09/17), `rs41.rs` (+ `rs.rs` Reed-Solomon, `geo.rs` ECEF). Channels that decode nothing for `TRY_FOR` are set aside for `RETRY_AFTER`. Engine runs it only after `Command::SetSondes(true)` (UI sends it in bands with `decoder = "radiosonde"`).
- `crates/radio/src/acars/` — aircraft messages (ARINC 618). Fixed `US_CHANNELS_HZ` inside the capture (bursts are too short for the detector to open a channel in time), all decoded all the time after `Command::SetAcars(true)` (UI sends it in bands with `decoder = "acars"`). `msk.rs`: mix + `Decimate` to 48 kHz, envelope, 24 kHz audio, mix by 1800 Hz, discriminator; 2400 Hz = bit same as last, 1200 Hz = differs; `PHASES` bit clocks with their own framers, duplicates dropped. `frame.rs`: SYN SYN SOH (inverted SYN flips the stream), odd parity, CRC-16/KERMIT after SOH through ETX/ETB, one bad-parity byte repaired against the CRC; downlinks (digit block id) carry MSN + flight. Status carries only `SEND_FOR` of messages; the panel (`lib/acars.ts` `mergeMessages`) keeps its own list.
- `crates/radio/src/rds/` — FM station data. `phy.rs`: pilot PLL ×3 → 57 kHz mixdown, Costas for residual phase, PSK-rate timing (reuses `sonde::fsk::Fsk`), biphase pairing by energy, differential decode. `blocks.rs`: sync needs two blocks in order, 2-bit burst correction, loss at >42 bad of 50. `mod.rs`: PS (0A/0B), RadioText (2A/2B), RT+ title/artist. Runs inside the WFM `Demodulator` on the 240 kHz MPX.
- `crates/radio/src/hd/` — HD Radio. `ffi.rs` dlopens libnrsc5 (loader path, then `~/.local/lib/libnrsc5.so`) and mirrors the header's event layouts — recheck them against `include/nrsc5.h` if nrsc5 is upgraded. `mod.rs`: `Hd` mixes the tuned station out, decimates to 800 kHz, cubic-resamples to 744187.5 S/s and pipes it to nrsc5 on its own thread; digital audio replaces analog after `PRIME_SECS` queued. Engine starts it silently (program 0, `play` off, analog keeps playing) once `sidebands` sees HD on the tuned WFM station, and plays it on `Command::SetHd(Some(program))`; `SetHd(None)` goes back to analog but keeps decoding. UI shows the HD panel whenever the decoder runs; it remembers the program per station in `state.json` (`hd`).
- `crates/radio/src/iss/` — space station passes, offline. `mod.rs`: SGP4 (`sgp4` crate) on the TLE cached at `~/.cache/squelch/iss.tle`, TEME→ECEF by IAU sidereal time, pass search (30 s steps, 1 s bisection). `fetch` uses `curl` against CelesTrak; the shell refreshes when the cache is >12 h old, trying at most every 2 h (CelesTrak blocks faster polling). `place.rs`: US ZIP centroids (`zips.txt`, Census 2020 ZCTA, 0.1°) and state centres (`states.txt`, area-weighted county points). UI (`lib/iss.ts`) widens passes by `slack` as the TLE ages, warns past 3 days, puts a dot on the rail's `iss` band while it may be overhead, and draws `IssMap.svelte` (d3-geo + world-atlas land-110m, offline) in the Space station panel from the `iss_track` command — whole world unless a pass is under way and the channel reads ≥ `RECEPTION_DB`; location lives in `settings.toml`, set in the Settings drawer, and also picks nearby repeaters.
- `crates/radio/src/p25/` — P25 Phase 1 public-safety trunking, `Mode::P25` (bands in group `safety`). `P25` (mod.rs) runs instead of the demodulator: searches carriers within `SEARCH_PPM` of the tuned control channel, follows unencrypted Phase 1 grants (retunes the dongle when the voice channel is outside the capture, restores it after), ends calls `HANG_SECS` after the last good LDU. Crystal error = control channel's own announced frequency vs where it was heard; applied to voice channels. Voice from another NAC (co-channel distant site) or with most frames damaged is muted. `phy.rs` C4FM at 48 kHz, timing per sync; `tsbk.rs` control messages; `voice.rs` LDU layout + DSD's IMBE interleave; `mbe.rs` dlopens mbelib (`pacman -S mbelib`), mirrors `struct mbe_parameters`. Verified live 2026-10-31 on Colorado DTRS site 3-55 (773.79375 MHz, NAC D17): 23 calls followed in 180 s, most 0–15% damaged frames. No BCH on the NID, no Phase 2.
- `crates/radio/src/adsb/` — aircraft (Mode S extended squitter, DF17/18) on 1090 MHz. `phy.rs`: magnitude of the whole capture, preamble gate then `PHASES` sub-sample starts, chips as area under the magnitude (1.2 samples each at 2.4 Msps), CRC-24 with one-bit correction. `msg.rs`: callsign, altitude (25 ft and Gillham), velocity, CPR fields; `cpr.rs`: even/odd pair (`PAIR_SECS`) then local against the last position (`LOCAL_SECS`), jumps past `MAX_KM_PER_SEC` dropped. `Adsb` keeps aircraft by address for `KEEP_SECS`, sample clock as time; a corrected frame never creates one. Engine runs it after `Command::SetAdsb(true)` (UI sends it on bands with `decoder = "adsb"`); status `adsb`. UI: `lib/adsb.ts` + `AircraftMap.svelte` in the Aircraft panel, distance from the Settings location. Synthetic I/Q (pulses area-sampled) decodes all frames at 17 dB per sample, 85% at 13.5 dB. No surface positions, no DF11/short replies, GNSS altitude ignored. Cost 2026-11-01 on eagle under load ~7: ~45 ms per second of noise-like capture, 170–290 ms on `bench`'s simulated FM capture (steady carriers pass the gate); unmeasured unloaded and live.
- `crates/radio/src/repeaters.rs` — parses RepeaterBook's Google Earth KML exports (per-state folders, last seen 2023-02-17, in a public Drive folder "Google Earth Ham Repeaters (United States)"). Per-mode files ("Colorado DMR.kml") tag modes by file name. Output `~/.config/squelch/repeaters.toml`, never committed (RepeaterBook data). Shell serves it as `repeaters` and emits `repeaters` on change; `channels.ts` `setRepeaters` makes it the channel plan of each ham band without a fixed plan. `lib/repeaters.ts` + `RepeaterMap.svelte`: the Repeaters panel on bands in `REACH_KM` (one guessed reach per band; the export has no power or height); repeaters also in a DMR/P25/NXDN/D-STAR/M17 file draw dashed as maybe digital-only. The panel is the map alone: the slider's `RANGES_KM` (`repeaters.range` in `state.json`), on-air circles carrying the call, wider for a stronger signal (`ringReach`), the title's pin opening Settings at the location. It reads `repeaters_map` (`within` `MAP_KM`, every repeater on a shared frequency), not the channel plan's nearest-per-frequency `repeaters`, so far repeaters have no channel name. Only imported states draw. The map's ground: `crates/radio/src/terrain.rs` fetches AWS Terrain Tiles (terrarium PNG, zoom 8, no key) with curl into `~/.cache/squelch/terrain/` (`terrain_tile` command); `lib/terrain.ts` shades them in theme colours (`GROUNDS`: one image per stop, zoom 8/7/6) and the result is saved in `~/.cache/squelch/ground/` under `groundKey` (`ground` / `save_ground`). Both caches prune least-recently-used past `MAX_TILES` / `MAX_GROUNDS` and anything unused for `MAX_AGE`. Best effort: no tiles, no shading. State lines and highways are bundled in `lib/maplines.json`, written by `python3 -I ui/scripts/maplines.py` (us-atlas states + Natural Earth roads).
- `crates/radio/src/record.rs` — records what is heard (the engine's `pcm` after squelch, before volume; HD and P25 audio included) to Ogg Opus. `Command::Record(bool)` makes a `Recorder`: the radio thread only sends chunks down a channel; a `record` thread encodes 20 ms packets with libopus (dlopened, `pacman -S opus`; mono, 32 kbit/s) and muxes with the `ogg` crate. Dropping the recorder (stop or engine exit) joins the thread and ends the stream, granule trimmed to the real length. Files: `<XDG music>/squelch/` (else `~/Music/squelch`), `2026-11-01T153012Z 101.100MHz wfm.opus` (UTC). State is a static read by the `recording` command; the top bar's record button (next to play, steady red when on) shows `m:ss` while recording and the saved file name after. Test records a tone and checks length with the `ogg` reader and `ffprobe`.
- Named and bookmarked are the only two ideas for a frequency (model, options and cuts: issue "Bookmarks and favourites overlap", 2026-11-01). Named: what it is for, known to the app: `names` on a band in `default_bands.toml`, name + `mode` (`bands::Name`). A user file without `names` takes them from the defaults by band id (`add_default_names`). Bookmarked: the user saved it (`bookmarks` in the bands file: `name`, `mode`, `notes`; `bands::upsert_bookmark` / `remove_bookmark` edit with `toml_edit`, so comments and layout stay, and `edit_file` writes via a temp file; a bookmark needs a band covering the frequency). Older files listed every shipped frequency as a bookmark with a `fav` star: `split_names` converts them once (marker `~/.local/state/squelch/names_split`), keeping what was starred, noted or renamed. `namedFrequencies` merges both, a bookmark replacing the name under it; labels, snapping and mode read that list, `saved` is bookmarks only. Waterfall: slim one-row cards above the signal (`LANES`), a card meaning tuned, then on air, bookmarked, a built-in name, and an ordinary channel only once zooming fits every one of them; what has no room is a dot (click tunes). Nothing clickable under the waterfall, nothing printed over it. The one bookmark control is the icon beside the top bar's name: saves under the name the frequency has, else its number; lit removes. `BookmarksScreen.svelte` (rail entry above the groups, `b`, Esc closes): every bookmark grouped like the rail, typing saves, a frequency tunes and returns to the waterfall, covers `main` without unmounting the waterfall. Rows scale by container query (mode goes first). The note and clock icons light when the row has one and open under the row. Channels panel lights bookmarked channels. Times to tune in (`SlotForm.svelte` under a row, `lib/schedule.ts`, a time belongs to a bookmark by frequency, `slotsAt`; others list at the screen's foot, `schedule.toml`, local time; several `times`, weekday toggles with an optional `week` of the month, or a one-off date; `minutes`, `action`, `go_back`). `action = remind`: the header shows a reminder chip from `LEAD_MS` before a start to `GRACE_MS` after, and the `notify` command runs `notify-send` once per start (best effort). `tune` / `record` (`runPlans` in `App.svelte`, each second): takes the radio for `minutes` with a bar above `main`, no notification, recording starts once status shows the frequency; another plan starting meanwhile shows as a chip. Waking: `wake.rs` writes `nextWake` (`WAKE_LEAD_MS` ahead) to the RTC wake alarm, writable after `squelch --setup-wake` (`wake::setup`: udev rule chowns it to the user, sudo once, password in the terminal; the form shows the command with `$APPIMAGE` or the binary's own path, and `runPlans` retries so it clears by itself; no pkexec: eagle runs no polkit agent, 2026-11-01; systemd's WakeSystem= needs root), and holds `systemd-inhibit` for sleep, idle and the lid switch through `awakeUntil`. All of it needs the app open.
- `crates/radio/src/prefs.rs` + `ui/src/lib/store.ts` — what the app keeps. Nothing goes in browser storage: WebKit keeps one store per origin, so `./run.sh` and release builds drifted apart (found 2026-11-01). `~/.config/squelch/schedule.toml` (`[[slot]]`, days by name) and `settings.toml` are the user's to edit, version and share: saves go through `toml_edit` so comments stay, unknown keys and bad values are errors, a file that does not parse is shown under Problems and never overwritten, and the 2 s poll emits `schedule` / `settings` on change. `~/.local/state/squelch/state.json` is this machine's memory (`getState` / `setState`, one JSON object, saved 1 s after a change). `main.ts` awaits `store.load()` before mounting, so `App.svelte` reads all of it synchronously. A slot's `id` is the page's own and stays the same across saves (`withIds`) so a form keeps focus; `at` is its place in the file. Verified 2026-11-01 on the release build with the simulator, driven over the WebKit inspector: hand edits appear, UI edits keep comments, a broken file is left alone, `localStorage.length` stays 0.
- `BACKLOG.md` — ideas not yet started, one line each. Append when the user says "add to the backlog"; delete the line when it ships.
- `ui/` — Vite root. `lib/radio.ts` holds pure logic (labels, card placement, snap-to-tune) with tests in `radio.test.ts`. `lib/channels.ts`: fixed channel plans (CB, FRS/GMRS, MURS, NOAA, marine, AAR rail) keyed by band id, so they apply even to an old user bands file; bookmarks and `names` still win over channel names. A band with a fixed plan gets the Channels panel (`channelList`: grouped, live dot from detected signals, click tunes). Except walkie-talkies: band `walkie` (old files' `frs_only`/`gmrs` alias to it) gets `WalkiePanel.svelte` — 22 tiles in three strips (`STRIPS` in `lib/walkie.ts`), the detail line tunes a repeater's input (+5 MHz, "18R") and back, tiles on the side outside the capture fade (462 and 467 MHz never fit one capture). Each minute either side is in the capture, `record` notes the channels on air (`walkie.history` in `state.json`, last `KEEP_MIN`); after `SHOW_AFTER_MIN` listened minutes the Activity tab (`WalkieActivity.svelte`) draws it, at most `COLUMNS` columns, blank where that side was not heard. Layout: `BandRail.svelte` (bands coloured per group by `theme.ts` `groupHue`, Settings drawer over the list, `s`), top bar (frequency: click closes the Bookmarks screen and centres it; name with the bookmark icon; transport, volume, squelch = draggable mark on the signal meter), then the waterfall `Pane` and at most one panel `Pane` beside it (stacked under 1000 px). `panels` in `App.svelte` ranks what is relevant; the first shows, the rest are tabs in its title. On FM, `BandStrip.svelte` at the top of the waterfall pane shows the whole band: ticks are stations heard on this or earlier runs (`lib/stations.ts`, `stations` in `state.json`, dropped after `MAX_AGE_MS`; grey = not heard this run; also keeps each station's name and RDS programme type, so FM cards have both before RDS comes in; the type is the card's second line) plus bookmarks; click a tick to tune, elsewhere to look there, drag the box to pan. `f` / double-click a title gives a pane the screen; F11 is full screen. Panel width `panel.size` and first-run hint `hint.seen` in `state.json`.

## Wire format
Spectrum rows and status: the page pulls them with the `feed` command (`src-tauri/src/feed.rs`, decoded by `lib/feed.ts`), one request at a time; the backend keeps the newest `MAX_ROWS` rows and the latest status, and a pull waits up to `BATCH_WAIT` for `BATCH_ROWS` rows (a status returns at once): 2026-10-31 this cut script evaluations from 34/s to 14/s and the page main thread from ~20% to ~16%. The body goes back as base64 in a `String`: on Linux Tauri 2.12 a raw `Response` body reaches the page JSON-encoded as a number array in release builds (dev gave an `ArrayBuffer`), found 2026-10-31 as a blank waterfall. Never push rows over a Tauri `Channel`: a row above 1 KiB costs an eval plus a fetch, and a page that falls behind queues them inside WebKit until its watchdog kills it (2026-10-31: ~2 MB/s growth, SIGABRT). A row is 8-byte f64 LE capture centre, then `FFT_SIZE` u8 bins. Byte 0 = `floor - BELOW_FLOOR_DB`, 255 = `RANGE_DB` above that (constants in `engine.rs`, sent to UI via `setup`).

## Commands
- Engine tests: `cargo test -p radio --release`
- Release binary that serves the built page: `pnpm build && touch src-tauri/build.rs && cargo build --release -p squelch --features tauri/custom-protocol` (or `pnpm tauri build`). A plain `cargo build --release` loads the dev URL and shows a blank window.
- Radio-thread profile: run with `SQUELCH_PROFILE=1`; every `PROF_EVERY` it prints the share of each stage to stderr (`Prof` in `engine.rs`). "read" is time waiting on the dongle.
- Real-dongle probe: `cargo run -p radio --release --example probe -- 101.1 wfm 4`
- Stage timings: `cargo run -p radio --release --example bench`
- UI tests / types: `pnpm test`, `pnpm check`
- Decode a recording: `cargo run -p radio --release --example sonde_file -- <wav>` (mono = FM audio, stereo = I/Q). Verified 2026-10-30 on rs1729's `rs41/wav/20140717_402MHz.wav` (RS41 K1930308, 114 frames) and `iq/dfmIQ.wav` (DFM-06 314377).
- HD Radio cost: `cargo run -p radio --release --example hd_bench` times the front end (`hd::FrontEnd`) and libnrsc5 on a second of noise. 2026-10-31 on eagle: front end 21 ms, nrsc5 122 ms (live with a signal the `hd` thread takes ~21% of a core, nearly all inside libnrsc5; a rebuild with `-DCMAKE_BUILD_TYPE=Release -DUSE_SSE=ON -march=native` measured the same live, 22.8% vs 21.8%, so the cost is the decoder's own). `hd_probe` right after another dongle user exits falls back to the simulator: wait a few seconds between runs.
- HD Radio live: `cargo run -p radio --release --example hd_probe -- 106.7 0 60 <dir>` prints decoder state and writes pictures (base64) to `<dir>`.
- ACARS live: `cargo run -p radio --release --example acars_probe -- <secs> [centre MHz]` prints every block (default centre 130.5 MHz covers 5 of the 6 US channels).
- RDS offline: `mpx_dump -- <MHz> <secs> <out.f32>` records MPX, `rds_file -- <out.f32>` prints pilot lock, block stats and decoded info.
- ADS-B live: `cargo run -p radio --release --example adsb_probe -- <secs>` tunes 1090 MHz and prints the aircraft table every 5 s.
- Space station passes: `cargo run -p radio --release --example iss -- <tle file> <zip | state | lat lon> [hours]`. Ground point matched api.wheretheiss.at to 0.01° on 2026-10-31.
- P25: `p25_scan -- <secs per step>` lists always-on carriers in 769–775 / 851–869 MHz (raw, crystal-uncorrected); `p25_probe -- <secs> <MHz>…` reports frame syncs, NAC, frame types and decoded TSBKs; `p25_live -- <control MHz> <secs> [out.f32]` follows calls and writes 48 kHz voice.
- Crystal error: `cargo run -p radio --release --example crystal -- 101.1` measures on a strong FM station, applies it, measures again.
- Live sweep of 400–406 MHz: `cargo run -p radio --release --example sonde_scan -- <secs per step>`.
- HD Radio sidebands across 88–108 MHz: `cargo run -p radio --release --example hd_scan -- <secs per step> [MHz… to profile]`.
- Repeaters file: `cargo run -p radio --release --example repeaters -- "Colorado All.kml" "Colorado DMR.kml" …` writes every on-air repeater; the shell keeps those within `NEARBY_KM` of the location (a state keeps all), nearest per output frequency.
- App: `./run.sh` (`pnpm tauri dev`; installs deps if missing, refuses while gqrx/SDR++ runs). `./run.sh sim` sets `SQUELCH_SIM=1` for the simulated receiver.

## Facts
- WebKitGTK on eagle (2-core i5-7360U, 2× scale) repaints and lays out on its main thread. No endless animation at all: even an `opacity` keyframe on the compositor keeps the whole window compositing at 60/s (measured 2026-10-31, release build); a state is shown by a steady style. One exception, the owner's call 2026-11-01: the Repeaters map's on-air circles (`.blip i`), which run only while a repeater in view is on air or within `HOLD_MS` of it; their cost on eagle is unmeasured. One-shot transitions only on `transform`/`opacity` of HTML elements (never SVG children, `box-shadow`, `width`); no `animate:flip` on a list rebuilt per status (it forces one page layout per row). Measured 2026-10-31 through `WEBKIT_INSPECTOR_HTTP_SERVER=127.0.0.1:9333` (Timeline and ScriptProfiler over its WebSocket).
- Waterfall: `lib/waterfall/gl.ts` keeps `ROWS` rows in a WebGL texture ring in capture coordinates and maps the view in the shader, so a row is one small upload and a zoom is two uniforms; `cpu.ts` is the 2D fallback; `waterfall = "cpu"` in `settings.toml` forces it (checked live 2026-10-31: draws, zoom lines up, page main thread ~6 points higher than WebGL). The spectrum line is a 2D canvas, one `Path2D` at one point per CSS pixel. The spectrum transform runs every `EVERY` frame (`spectrum.rs`).
- DSP hot paths (`dsp.rs`): FIR dot products and the mixer have AVX2+FMA kernels chosen at runtime (`has_avx`), with plain twins the tests compare against; `Decimate::new(rate, pass, stop, factor)` splits an even factor ≥ 4 into two stages; `fast_atan2` (≤ 2e-5 rad) for FM discrimination and the pilot PLL, which runs per `BLOCK` (`rds/phy.rs`). Bench 2026-10-31 on eagle: WFM 105 → 26 ms per second of capture, NFM 58 → 16, AM 56 → 9, USB 101 → 14, sondes 183 → 77.
- eagle is a MacBookPro14,1; logind's lid action is hibernate (`/etc/systemd/logind.conf.d/30-lid.conf`), `/sys/power/disk` mode shutdown, `mem_sleep` deep. Whether the RTC alarm wakes it from either, and whether the engine's dongle reopen (a read error closes and reopens `RtlSdr`) works after resume, is unverified as of 2026-11-01: testing means putting the machine to sleep.
- Dongle on eagle: generic RTL2832U + R820T, 24–1766 MHz, no HF. DVB driver blacklisted in `/etc/modprobe.d/blacklist-rtlsdr.conf`.
- Moving or zooming the view never restarts audio: `Command::Tune` clears audio and squelch only when `tuned_hz` changed (test `repeating_a_tune_leaves_the_channel_alone`: 2026-11-01, 46.6 dB still vs 19.2 dB dragging before the fix). `captureCenter` keeps the tuned frequency in the capture as long as view and tuned fit within `rate * 0.45` of one centre; past that the view wins and the engine mutes rather than play the alias. A centre move still flushes queued samples; HD keeps decoding (`Hd::set_offset`, each queued block carries its offset), riding out the gap on its audio queue. Unit-tested 2026-11-01; not yet heard live.
- Capture is 2.4 Msps (`SAMPLE_RATE`); UI view span capped at 0.8× that. Wider views would need sweeping — not built.
- User bands file: `~/.config/squelch/bands.toml`, written from defaults on first start. `bands::add_new_defaults` then adds default groups/bands not listed in `~/.local/state/squelch/default_bands_seen` (ids offered before); with no record yet, only whole missing groups. Edits and deletions are kept.
- Theme source: `~/.local/state/omarchy/current/theme/colors.toml`.
- Sonde types near eagle (NWS list 09-25): every nearby site flies GRAW DFM-17; Denver (KDNR) lists none. RS41 is the other US type. Simulator includes a DFM-17 at 403.3 MHz.
- `cargo build` while `pnpm tauri dev` is rebuilding corrupts the shell crate's link (undefined hidden symbol): stop dev, `cargo clean -p squelch`, rebuild. If that still fails (2026-11-01: it did, after a clean of the shell crate alone), `cargo clean --profile dev`; the rebuild took 9 min on eagle.
- The dongle streams via `rtlsdr_read_async` on its own thread into a `QUEUE`-buffer channel. Blocking `read_sync` dropped 15–25% of samples (found 2026-10-30: rows/s ~24 not 30, pilot phase random, RDS dead).
- eagle's dongle crystal runs ~57 ppm fast: FM carrier offset on 101.1 MHz, 2026-10-31 (`crystal` example); after correcting 57, residual ~1 ppm. The engine measures it on any strong FM station tuned on the 100 kHz grid (`MEASURE_SECS`, `MEASURE_SNR_DB`) or a P25 control channel; the UI applies it via `set_ppm` (librtlsdr `rtlsdr_set_freq_correction`, positive = crystal fast) unless set by hand in Settings: by hand is `crystal_ppm` in `settings.toml`, measured is `ppm.measured` in `state.json`.
- libnrsc5 is not packaged: build theori-io/nrsc5 with cmake (CLI needs system `libao`), copy `build/src/libnrsc5.so` to `~/.local/lib`. Without it the HD panel shows the install hint. GPL-3; its audio codec is patented.
- Only one program can hold the dongle; close gqrx/SDR++ first.
